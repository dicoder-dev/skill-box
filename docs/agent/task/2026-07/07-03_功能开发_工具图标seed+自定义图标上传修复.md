## 4. 问题与方案

### 4.1 编辑工具弹窗上传自定义图标失败

**现象:** 用户在 ToolsView 弹窗点"上传自定义图标"按钮选完文件,toast 弹"上传失败:..."(具体消息取决于后端/网络层报回)。

**根因:** `frontend/src/core/utils/requests/http.js:64-66` 中
```js
body: body !== undefined ? (typeof body === 'string' ? body : JSON.stringify(body)) : undefined,
```
对所有非 string body 都走 `JSON.stringify`。当 body 是 `FormData` 时:
- `JSON.stringify(formData)` 返回 `"[object FormData]"` 字符串 — 完全不是 multipart 数据
- 同时调用方又把 `Content-Type: multipart/form-data` 设到 header,fetch 看到这个 string body + multipart content-type,
  边界(boundary)也对不上,后端 gin 拿到的是空 form / 缺失 `file` 字段
- 后端 `ctool/upload_icon.a.go:53` `req.File == nil` 判定失败,返 400 `missing file field`
- 前端拿到 400,response 拦截器剥不到 `code` 信封,`HttpError.message = "HTTP 400 ..."` 抛到 ToolsView onIconFileChosen,
  toast 显示"上传失败: HTTP 400 ..."

**方案:** `http.js` 的 body 序列化逻辑里加一条:**body 本身是 `FormData` / `Blob` / `URLSearchParams` / `ArrayBuffer` / `ReadableStream` 等"自带传输协议"的类型时,直接原样传,不要 JSON.stringify,也不要手动覆盖 Content-Type**(让浏览器 fetch 自动带 boundary)。

修完后:
- 调用方只需要传 `FormData`,不再需要手动设置 `Content-Type` header(虽然设了 fetch 也会自己忽略)
- 旧的 `'Content-Type': 'multipart/form-data'` 选项可以保留(防御性),但更推荐**删掉**(避免被外行误改)
