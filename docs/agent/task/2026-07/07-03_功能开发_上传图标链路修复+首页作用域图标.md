## 4. 问题与方案

### 4.1 上传"掉色没反应图" — 3 层 bug 叠加

#### Bug A: pkg/ginp/bind_handler.go 对 multipart 路由仍走 ShouldBindJSON

**现象:** 后端返 `{"code":0,"msg":"请求参数有误: invalid character '-' in numeric literal"}`

**根因:** `pkg/ginp/bind_handler.go` 第 82-89 行的 `switch c.Request.Method` 没有看 Content-Type,POST 全部 `ShouldBindJSON`。但上传是 `multipart/form-data`,body 不是 JSON → `ShouldBindJSON` 解析 multipart 字符串时碰到 `-` 字符当成 JSON 数字失败。

**修复:** 看 Content-Type,multipart/form-data 走 `ShouldBindWith(binding.Form)`,其它维持。

#### Bug B: gin form binding 对 multipart.FileHeader 字段是 no-op

**现象:** 修完 Bug A 后,错误变成 `Key: 'RequestUploadIcon.File' Error:Field validation for 'File' failed on the 'required' tag`。

**根因:** gin 的 form binding (vendor/.../binding/form_mapping.go) 对 `case multipart.FileHeader: return nil` —— **不做任何绑定**。这是 gin 的设计:form binding 只绑 string/数字字段,文件需要手动 `c.FormFile("name")`。

**修复:** `upload_icon.a.go` 改用 `BindHandler` + `c.FormFile("file")` 手动拿文件,删 `RequestUploadIcon` struct。

### 4.2 首页 TreeNode chip 图标硬编码 mdi

**现象:** SkillsView 左侧 skill 树里,每个 skill 的"工具 chip"(claude/codex/...)前面用的是 mdi 图标(如 `mdi:robot-outline`),不是真实 logo。

**根因:** `TreeNode.vue` 第 144-150 行硬编码 `TOOL_ICON_MAP = { claude: 'mdi:robot-outline', ... }`,跟 ToolsView 的 `ToolIcon.vue`(icon_file 优先 + mdi 兜底)不一致。TreeNode 不知道 tool 元数据,只能这样。

**修复:**
- `TreeNode.vue` 加 `toolsById` prop + `toolIconFile(tid)` 函数 + `<img>` 优先 + mdi 兜底。
- `SkillsView.vue` 注入 `useToolsStore()`,computed 出 `toolsById` map,onMounted 首次拉一次。
- `TreeNode.vue` 模板 `<Icon :icon="toolIcon(tid)">` 改成 `<img v-if="toolIconFile(tid)" :src="...">` / `<Icon v-else>`。

### 4.3 http.js 给 GET 也加 Content-Type

**现象:** 实测时 GET /api/skillbox/tools 也走 `Content-Type: application/json`(虽然没 body)。BindParamsHandler 之前没 Content-Type 检查,看到 application/json 走 ShouldBindJSON,GET 没 body → EOF 报错。

**修复:** http.js 只在 POST/PUT/PATCH 设默认 Content-Type,GET/DELETE 不设。
