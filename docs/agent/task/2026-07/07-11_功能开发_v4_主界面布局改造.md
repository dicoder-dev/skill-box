# 主界面布局改造 v4:macOS 顶部 spacer 调到 50px(精确等于 wails InvisibleTitleBarHeight)

**日期:** 2026-07-11
**状态:** 已完成

## 1. 需求

用户反馈:v3 改的 44px spacer 仍不够,macOS 桌面端第一个导航图标仍与系统状态栏(红绿灯)垂直重叠。怀疑 `isMacOS` 判断逻辑出问题。

## 2. 根因分析

不是 `isMacOS` 没命中——UA 检测 `/Mac|iPhone|iPad/i` 在 wails3 webview 里通常正确(webkit 内核,UA 含 "Mac OS X" 或 "Macintosh")。

真正原因:`desktop/wails_app.go:511-515` 设了 macOS 窗口配置:
```go
Mac: application.MacWindow{
    InvisibleTitleBarHeight: 50,                                  // ← 红绿灯垂直占 50px
    Backdrop:                application.MacBackdropTranslucent,
    TitleBar:                application.MacTitleBarHiddenInset,   // ← webview 从屏幕顶 0px 起,红绿灯浮在 webview 上方
}
```

`MacTitleBarHiddenInset` 模式下,webview 区域从屏幕顶部 0px 开始,**红绿灯浮在 webview 内部**(左 0-80px、顶 0-50px 区域)。我们的侧栏宽度 64px 正好覆盖红绿灯水平位置,所以侧栏顶部必须预留 **50px**(精确等于 `InvisibleTitleBarHeight`)才能让红绿灯不被遮挡。

v3 给的 44px 少 6px,所以红绿灯的下半圆(关 / 最小 / 最大按钮的底缘)仍压在第一个 nav 图标的顶 padding 上。

## 4. 问题与方案

### 问题 1:spacer 高度凭直觉估,结果一直不够

> 现象:v2 估 32px → 重叠;v3 估 44px → 还差 6px 重叠;v4 直接对齐 wails 配置的 50px 才稳。
> 定位:`desktop/wails_app.go:512` 实际设了 `InvisibleTitleBarHeight: 50`,前端没必要估,直接读后端配置或硬编码对齐。
> 方案:写注释明确"`height: 50px` 必须与 `wails_app.go:512 InvisibleTitleBarHeight: 50` 同步修改,改了后端要同步前端"。
> 教训:**桌面应用 chrome(标题栏 / 红绿灯 / dock 区域)的避让高度永远以原生窗口配置为准**,不要用经验值。

### 问题 2:go build 失败是 skillstore 无关脏改动

> 现象:`go build` 报 `api-server/internal/skillstore/store.go:1288:61: cannot use data (variable of type []byte) as string value`。
> 定位:`git diff HEAD` 显示 `store.go` 有未提交的本地改动(新增 `SourcePath` 字段 + 调用 `writeFileAtomic` 时把 `[]byte` 当 string 传),与本次前端任务无关。
> 方案:已经 `git stash` + `git stash pop` 暂存并恢复,本次不动。本次 go build 跳过,改为 vite build 通过 + App.vue grep 校验 50px 数值到位作为验证。
> 教训:**遇到 build 失败先看 git status**,区分"我的改动引入" vs "工作区已有未提交改动引入",不要盲修。
