# AI 历史 v2 用户反馈修复 · 路由未注册根因补记(2026-07-14 深夜)

**日期**:2026-07-14 23 时许(继 `14_AI历史v2用户反馈修复` 之后)
**状态**:已修复(commit 待提交)
**触发**:用户在 wails3 dev 复测,POST `/api/skillbox/ai/history/save` 仍 404(12.5µs)

## 1. 真根因(极简)

`api-server/internal/gapi/router/routers_import.go` **漏 import** `caisession` 包。

后果:
- caisession 包 4 个 controller 的 `init()` 全都不执行
- `ginp.RouterAppend(...)` 全不生效
- Gin 收到 POST 请求 → 默认 404 handler → 12.5µs 返回
- **resolveSkillDirBySourcePath 根本没机会执行**,前次加的 `logger.Warn` 看不到任何东西

数据印证:
```
[127.0.0.1] POST /api/skillbox/ai/chat          | 200 | 1.122574208s   ← 走通
[GIN]    2026/07/14 - 21:10:54 | 200 | 1.122574208s | POST /api/skillbox/ai/chat

[127.0.0.1] POST /api/skillbox/ai/history/save | 404 | 12.5µs         ← Gin 默认 404
[GIN]    2026/07/14 - 21:10:55 | 404 | 50.083µs   | POST /api/skillbox/ai/history/save
```
12.5µs / 50µs 都是 `gin.Engine.NoRoute` 默认 handler 的特征:不到业务层、不打应用日志、纯 router level。

## 2. 为什么漏了

v2 commit 把 4 个 controller 文件落到 `caisession/`,但没有回去同步更新
`routers_import.go`。后端框架的路由注册是"哨兵 import"模式:

```go
// routers_import.go
import (
    _ "ginp-api/internal/gapi/controller/skillbox/caiprovider"
    _ "ginp-api/internal/gapi/controller/skillbox/cdesktop"
    // 缺 _ ".../caisession"      ← 这里漏了
    // ...
)
```

每个 controller 文件都有 `func init() { ginp.RouterAppend(...) }`,
**只有包被 import** 时 init 才会被运行时调用。

所以凡是这里列出来的包名,startup 时 4 个 history 路由才进 `gin.Engine`。
列得不全 = 那一包下所有 controller 的路由全 404。
caisession 包内 v2 之前的 4 个 controller 都不存在,从未被 list 到,
所以漏 import 在 v2 之前不报错 → v2 加完 controller 文件,没人补 import 这行。

**完全是我 v2 时的疏忽**——加完 controller 没回头刷这个哨兵 import 列表。

## 3. 修复

`api-server/internal/gapi/router/routers_import.go`:

```diff
 import (
     _ "ginp-api/internal/gapi/controller/skillbox/caiprovider"
+    _ "ginp-api/internal/gapi/controller/skillbox/caisession" // 2026-07-14 增:补 import,否则 4 个 ai/history 路由没注册,Gin 默认 404
     _ "ginp-api/internal/gapi/controller/skillbox/cdesktop"
```

按字母序插入 caiprovider ↔ cdesktop 之间。

## 5. 教训

**凡是用"哨兵 blank import"做 init 触发的项目,加新 controller 包必须同步刷两个位置**:
1. controller 文件本身的 `init() ginp.RouterAppend`
2. `routers_import.go` 的 `_ "..."` import

可以加 CI grep / goleak 检查:
```bash
# CI 校验:控制器包目录下存在 *.a.go,必须在 routers_import.go 出现对应 import
```

或者更彻底:把控制器的 init() 改成显式注册入口(例如 `Register(engine *gin.Engine)`),
`routers_import.go` 改成统一调 `RegisterAll(engine)`。这样不会漏。

(本轮不重构,只补 import,防止 scope creep。)
