## 4. 问题与方案

### 问题 1:后端没把 os 注入 __APP_RUNTIME__

> 现象:`platform/index.js` 的 `platform.platform.os()` 在 desktop 模式下读 `window.__APP_RUNTIME__.os`,但 `api-server/cmd/bootstrap/server.go:226 buildRuntimeScript()` payload 只塞了 runMode / needAuth / appName 三个字段,os 没注入,所以实际拿到的是兜底的 'desktop'。
> 定位:grep 后端 runtime 注入代码 + 平台抽象代码确认 payload 结构。
> 方案:本轮不引入后端改动,直接用 `navigator.userAgent` 兜底。只在 `runMode === 'desktop'` 才做平台判断,web 端永远贴顶(没有红绿灯顾虑)。
> 教训:**前端需要的运行时元数据如果后端没注入,先用 UA 兜底**,避免为了一个布尔判断改后端 + 重新走 wails3 dev 链路。

### 问题 2:上次 Edit 残留两个 `</template>`

> 现象:grep 出 322 行有孤悬 `</template>`,导致 SFC 边界混乱。
> 定位:上次重写 template 时 new_string 末尾没有 `</template>`,old_string 末尾却匹配到一个 `</template>`,替换后留下了旧尾巴。
> 方案:每次大段 Edit 后跑 `grep -n "^<script\\|^</script\\|^<template\\|^</template\\|^<style\\|^</style" 校对 SFC 边界。
> 教训:同上一轮问题 1,应一次 Write 全文替换,或每次 Edit 后立刻校验 SFC 边界。
