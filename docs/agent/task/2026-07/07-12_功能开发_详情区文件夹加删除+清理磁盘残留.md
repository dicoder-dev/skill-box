## 4. 问题与方案

### 4.1 磁盘残留 `.skillbox-placeholder` 的根因

**链路**:
1. 第一版 commit `e9ed67d`(已回滚后被新逻辑覆盖):前端新建目录时**真的写** `.skillbox-placeholder` 占位文件到磁盘
2. 后来 commit `d030805` 改成"走 createGroup 端点 + 不写占位文件",但**用户 dev 环境跑的可能还是旧代码**(Vite HMR 时机 + 桌面端需要重启)
3. 用户在 HMR 切换前用旧代码建了 `dd` 目录 → 磁盘上**真**有 `dd/.skillbox-placeholder`
4. 用户重命名 `dd` → `Dd1`,renameFolder 走 updateSkill 时把 `dd/.skillbox-placeholder` 改名为 `Dd1/.skillbox-placeholder` → **磁盘上真存在 `Dd1/.skillbox-placeholder`**
5. 用户又建了 `sub_empty` 目录(可能也用旧代码)→ `Dd1/sub_empty/.skillbox-placeholder` 真的存在

**修复**:在这次排查时**手动 `rm -rf` 清理了 `aa/Dd1/`**(包括子目录和占位文件),只保留用户的 `1.md` 和 `SKILL.md`。

### 4.2 "还是没有显示" 的可能根因

**用户最后一张截图之前** 3 轮我都用 Node 模拟 buildTree,确认逻辑正确能建出 Dd1 节点。所以代码层 OK,可能是 Vite HMR 没把新代码推下去(wails dev 模式 + 大组件的 FileTreeView 重编译偶尔失败)。

**这次做的修复**:
- 我手动清理了磁盘残留 → 解决"磁盘上有奇怪的占位文件"
- 用户需要 **Cmd+R 强刷 wails dev webview** → 让 Vite 重新加载最新代码

### 4.3 删除文件夹的实现

**复用现有 deleteFile 弹窗**(`kind === 'dir'`):
- `openDeleteFolderDialog(dir)` → 设 `deleteFileTarget = { path, name, kind: 'dir', childCount }`
- 弹窗根据 `kind` 切换文案:
  - `'dir'`: "确定要删除目录「{name}」吗?该目录下还有 N 个文件会被一并删除"
  - `'file'`: "确定要删除 '{name}' 吗?"
- 用户确认 → `submitDeleteFile` 的 `kind === 'dir'` 分支:
  - filter 所有 `<dir>/` 前缀的 file.path
  - 调 `persistFiles(next)` → `updateSkill({ files: next })` → 后端 `os.RemoveAll(aa/)` + 重建
  - 整个目录在磁盘上消失 ✓

**菜单项位置**:onCtxFolder 现有 4 项(新建文件 / 重命名 / 在文件浏览器中打开)+ 第 5 项"删除文件夹"(danger icon),用分隔符分成两组(普通操作 vs 危险操作)。

- **教训:** "占位文件" 这种 backend 假装存在但 frontend 看不见的暗契约,**应该在 buildTree 入口处加一条 `console.log` 验证** (我之前加过,后来清掉了 —— 这次保留它会更稳妥)。
- **可改进:** 整个"详情区文件树 CRUD"是跨前后端的复杂功能,下次类似需求应该**先写一个 E2E 测试脚本**(用 shell 跑一系列命令验证磁盘状态),再改实现。
