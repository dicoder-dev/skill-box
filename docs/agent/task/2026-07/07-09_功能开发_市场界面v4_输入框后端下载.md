# 市场界面 v4:按市场显示安装机制 + 输入框后端下载

**日期:** 2026-07-09
**状态:** 进行中(方案设计完成,等待用户最后确认后开干)

## 1. 需求

用户原话:
> 完善一下市场界面,是点击对应的市场时把对应的市场的 skill 如何安装到 skill-box 上在界面上显示出来;
> 你同时也要联网搜索对应的市场的 skill 安装机制并分析出如何配合其暗转蛋糕 skill-box 里面,
> 给用户提供一些思路,亦或是用户可以复制对应的 skill 网址 我们这边后端可以直接下载到本地(我推荐这个方案)
> 在市场界面预留给用户输入的 skill 名称或者详情页地址

核心诉求:
1. 当前 MarketView v3 只有"在浏览器中打开"按钮,缺安装指引 + 直接拉取能力
2. 按市场(SkillHub / Skills.sh)展示该市场的安装机制(命令、URL 形态)
3. 用户复制详情页 URL / skill 名 → 后端直接下载到本地 skill-box
4. UI 不能空,所有阶段有进度反馈

### 三方市场安装机制分析(联网结果)

| 市场 | 详情页 URL | 安装 URL/命令 | skill 物理形态 |
|---|---|---|---|
| SkillHub | `https://skillhub.cn/skills/{slug}` | 浏览器人工 / 后端 `/api/v1/download?slug={slug}` 302→COS zip | zip 包,内含 SKILL.md(可嵌套) |
| Skills.sh | `https://skills.sh/{owner}/{repo}/{skill}` | `npx skills add {owner}/{repo} --skill {name}`(走 GitHub raw) | GitHub 仓库 `skills/{name}/SKILL.md` |

| 通用 GitHub | `github.com/{owner}/{repo}/tree/main/skills/{name}` | `raw.githubusercontent.com/{owner}/{repo}/main/skills/{name}/SKILL.md` | 同上 |

## 3. 方案

### A. 后端 — 新增「输入框下载」接口

**新增 controller**:`api-server/internal/gapi/controller/skillbox/cmarket/install_from_input.a.go`
**新增 service 方法**:`smarket.InstallFromInput(ctx, *InstallFromInputInput) (*InstallFromInputResult, error)`
**HTTP 端点**:`POST /api/skillbox/market/install-from-input`

**入参**:
```go
type RequestInstallFromInput struct {
    SourceID uint   `json:"source_id"` // 0 = auto(按 input 推断);非 0 = 用指定源
    Input    string `json:"input"`     // 用户原文(slug / URL / owner/repo@skill)
    Scope    string `json:"scope"`     // global(默认) / project
    ProjectID uint  `json:"project_id"`
}
```

**解析规则**(在 service 层做,放在新文件 `smarket/install_input_resolve.go`):
```
auto 模式(input 整体):
  1. 含 "://" → 走 URL 解析
     a. host = skillhub.cn → sourceID = skillhub,remoteID = 末段 /skills/{slug}
     b. host = api.skillhub.cn → 转成 skillhub.cn 的等价 URL
     c. host = skills.sh → sourceID = skillssh,remoteID = {owner}/{repo}@{skill}
     d. host = github.com 或 raw.githubusercontent.com → 走 github resolver
        - GitHub URL 解析出 owner/repo/path
        - path 必须含 SKILL.md,推断 skill 子目录
        - canonical.SkillsSH.Download 走 raw URL 即可(skillssh adapter 内部已有 GitHub raw 支持)
     e. host = 其它 → ErrInvalidInput
  2. 不含 "://" → 按 sourceID 走:
     a. sourceID = skillhub → remoteID = input(slug)
     b. sourceID = skillssh → remoteID = input(owner/repo@skill 格式,正则校验)
```

**实现要点**:
- 解析函数纯函数:`func ResolveInstallInput(input string, defaultSource string) (sourceType string, remoteID string, err error)`,便于测试
- 复用现有 `Orchestrator.DownloadFromSource(ctx, sourceID, remoteID)` 拿 canonical
- 复用 `sskill.Service.Create` 落 store(skillstore DB),`SourceDir` 走 EvalSymlinks
- 复用 `smarket.PullV2` 的写盘后段(去掉 source_id/remote_id 校验,改成直接拿 sourceID 调 Download)

**响应**:
```go
type RespondInstallFromInput struct {
    Stage         string `json:"stage"`          // resolve/download/extract/write/done
    SourceType    string `json:"source_type"`
    SourceName    string `json:"source_name"`
    RemoteID      string `json:"remote_id"`
    ResolvedURL   string `json:"resolved_url"`   // 后端实际访问的 URL(调试用)
    SkillName     string `json:"skill_name"`
    SkillVersion  string `json:"skill_version"`
    Scope         string `json:"scope"`
}
```

**进度事件**(走 SSE 还是 polling?):
- 决策:**HTTP 响应一次返回**(实际下载 zip 几秒内完成,不需要 SSE)
- 前端用"进度条"模拟多阶段:解析 URL → 下载 → 解压 → 写盘,前端 setInterval 推进度百分比,后端完成后跳到 100%

**新增 service 文件**:
- `smarket/install_input.go`:输入解析函数 + InstallFromInput service 方法
- `smarket/install_input_test.go`:解析函数单测(slug / URL / 多种格式)

**新增 controller 文件**:
- `cmarket/install_from_input.a.go`:HTTP handler + init 路由

**安装流程**:
1. 用户输入 → 点「装到 skill-box」
2. 前端 `installing.value = true`,启动进度条动画(0%→25% 解析 / 25%→60% 下载 / 60%→85% 解压 / 85%→100% 写盘,每阶段 800ms 平滑过渡)

4. 成功 → toast「✅ 已装入 {skill_name} v{version}」+ 「去首页查看」按钮
5. 失败 → 在输入框下方显示错误原因(红色提示条),保留输入内容
