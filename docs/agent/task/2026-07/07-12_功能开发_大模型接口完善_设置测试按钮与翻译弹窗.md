## 4. 问题与方案

### 4.1 后端 TestConnection 的 ctx.Done() 退出路径

**现象:** 第一版 select/for 的 ctx.Done() 分支没 return,会一直消费 channel,行为不安全。

**方案:** 让 ctx.Done() 直接 return 一个 TestResult,channel 关闭路径走单独 case。详见
`internal/gapi/service/ai/sai/ai.s.go` 的 TestConnection 实现。

### 4.2 controller 风格漂移

**现象:** caiprovider 既有 controller 都用 `c.JSON(...)` 而非项目规范要求的
`c.SuccessData / c.Fail`,已有沉淀。

**方案:** 不改旧 controller 行为一致性,新增 test_provider.a.go 沿用 `c.JSON`。
设"风格统一"类 PR 单独开,与本次需求隔离。

### 4.3 AIPanel → AIDialog 的语义迁移

**现象:** 旧 AIPanel 是嵌入 SkillsView 右侧的边栏(v-if 控制显示)。
按需求要改成"独立全局弹窗"——同一组件,不同渲染位置。

**方案:** 用项目已有的 `<Modal v-model>` 包壳,弹窗用 aiOpen 双绑;选择 action 后切
step 进入子面板(翻译/优化),流式渲染结果。新建组件 `AIDialog.vue`,旧 AIPanel.vue
**未删除**(用户未要求删),保留为备选,后续清理时一并处理。

### 4.4 i18n 缺失 key 导致 build 时静默用原 key 字串

**现象:** `common.loading` 在 zh-CN/en-US 都没有,模板里 {{ t('common.loading') }}
在运行时输出 "common.loading" 不会报错。

**方案:** 顺手补上 `common.loading`,不破坏其它无此 key 的 component。
