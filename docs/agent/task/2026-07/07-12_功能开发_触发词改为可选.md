# 触发词改为可选

**日期:** 2026-07-12
**状态:** 已完成

## 1. 需求

用户反馈:首页中"新建"或"编辑技能"的弹窗,触发词不一定必须填写,即触发词改为可选。
命中两处路径:`SkillFileInlinePanel` 的 frontmatter 表单(实际生效的入口)和 `SkillsView`
旧版 `editorOpen` Modal(目前作为 `startNew` 失败时的兜底)。
需要保证两处校验、UI 提示、payload 三处一起改。

## 4. 问题与方案

> 设计取舍:可选 = "完全不拦用户",而非 "静默填一个默认值"。
>
> - 把必填校验从 `if (triggers.length === 0)` 改成删除整段,不引入"自动塞个 'untitled'"
>   之类的默认值,避免污染数据。
> - payload 用 `...(triggers.length ? { triggers } : {})` 而不是 `{ triggers: [] }`,
>   保证 manifest JSON 体根本不包含 triggers 字段,与"未填"的语义一致。

> InlinePanel 文案约束:跟 `SkillFileInlinePanel` 已有的"0 个 t() 调用"硬约束保持一致,
> 新增"可选"和"空态提示"两个文案走组件顶部 `LABEL_TRIGGERS_OPTIONAL` /
> `LABEL_TRIGGERS_EMPTY_HINT` 常量,不用 plainT/messages(否则会触发已记录的 Proxy 抛错)。
> SkillsView 旧 Modal 仍走 `useI18n().t('skills.editor.xxx')`,无此约束。
