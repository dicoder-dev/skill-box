## 4. 问题与方案

### 4.1 tar 流式 reader 的延迟 open 问题

**现象:** `readTarEntries` 第一次写时用 `io.NopCloser(io.LimitReader(tr, size))` 作为 entry 的 open 函数,返回 0 字节。

**根因:** tar.Reader 是流式的 — `Next()` 之后 payload 只能从 tr 读一次。后续多次 open 时,tr 已经被消耗,LimitReader 也读不到了。

**方案:** 在 read 阶段立刻把 payload 缓冲进 `[]byte`(受 maxEntryBytes 限流),open 时直接 `bytes.NewReader`。trade-off 是 tar 整体解压到内存,但 skill 包一般几 MB,够用。

### 4.2 tar 无 magic bytes

**现象:** `detectArchiveKind` 对纯 tar 返 `archiveUnknown`,测试 `TestImportFromArchiveBytes_Tar` 失败。

**根因:** 纯 tar 没有固定文件头 magic(不像 zip/gzip/bzip2/xz)。

**方案:** 加 `hasUSTARMagic` 检测 tar header offset 257 处的 `"ustar\0"` 标识(POSIX/GNU 都遵循)。

### 4.3 Windows 反斜杠 zip

**现象:** 用户 deepwhite zip 报"未找到 SKILL.md"。

**根因 1:** zip.Reader 直接读 `f.Name = "deepwhite-screenwriting-v1\\SKILL.md"`(反斜杠原样保留),`path.Base` 把整条字符串当 basename,检测不到 SKILL.md。

**方案 1:** 在 entry 入库时调 `normalizeArchivePath` 把 `\` 转 `/` + 清理 `//`。

### 4.4 SKILL.md 顶层、附属 file 在更深子目录

**现象:** 加了 normalize 后,SKILL.md 检测到了,但附属文件 `references/engine.md` 仍被丢。

**根因:** 旧 `groupEntriesBySkillDir` 按 `path.Dir(entry)` 分组,然后过滤"含 SKILL.md 的组"。但 SKILL.md 在 `deepwhite-screenwriting-v1` 组,`engine.md` 在 `deepwhite-screenwriting-v1/references` 组,后者没 SKILL.md 被过滤掉。

**方案:** 改成"沿祖先目录找最近的 skillDir"——对每个 entry 向上 walk,找最近的含 SKILL.md 目录作为分组 key。
