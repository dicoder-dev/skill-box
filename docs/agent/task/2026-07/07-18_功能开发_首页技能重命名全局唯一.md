## 4. 问题与方案

### 4.1 用户强调"全局唯一",不只是分组唯一

原 `RenameSkillInGroup` 只在同分组 `os.Stat(dstAbs)` 做冲突检测,漏掉"根下 foo 改名 bar 但 aa/bar 已存在"这种跨分组冲突。

**方案**:在 store 加 `SkillNameExistsAnywhere(name) bool`,复用 `findByName` 的 BFS(浅层优先),零新增 IO 路径;在 `RenameSkillInGroup` 内 `Stat(dstAbs)` 之前调用一次。错误消息保留 `"already exists"` 关键字,controller 把它映射到 `409 + code=target_exists`,前端契约零改动。

### 4.2 全局唯一的 scope 边界

调研后明确:**skillbox store 内**全树唯一。依据:store 是单一物理根 `~/.skill-box/skills/`,adapter(scope)是 apply 层概念,各自有不同物理根,store 改名不影响 adapter,也不需要跨 adapter 查重。后续如果 scope 范围要扩(比如用户提到"不管它在哪个分组"),现有 API 已经天然覆盖(只要在同一个 store 物理根)。

### 4.3 store `findByName` 已浅层优先,符合预期

`findByName` 注释明确"浅层优先:根下的 skill 优先于分组里的同名 skill",这跟产品直觉一致 — 根下赢。`SkillNameExistsAnywhere` 直接复用,不需要再写遍历函数。

### 4.4 乐观更新失败回滚策略

`renameSkill` 乐观更新先改 tree 节点 name + path,失败时整体 `load()` reload 回滚(简单可靠,树规模 < 200 节点)。不写复杂的局部回滚,跟 `renameGroup` 写法对齐。

### 4.5 selectedPath 跨 tab 持久化协同

`selectedPath` 持久化在 localStorage(`skillbox:skill-tree:last-selected-path`),改名后若当前选中就是它,直接同步写 localStorage,避免下次 mount 时用旧 path 找失败。

### 6.3 边界 / 异常

- [x] 同名不改 → `same` 错误,不调用后端(`if (oldName === newName) return ok` 短路)。
- [x] 非空校验 → 弹窗红字 `名称非法`,不送后端。
- [x] 非法字符 `Foo Bar!` → 本地预校验 `/^[a-z0-9_-]+$/` 失败,弹窗红字,不送后端。
- [x] 跨分组同名 → 后端返 `already exists`,前端映射到 `skillRenameConflict` 红字"该名称已存在,请换一个全局唯一的技能名称"。
- [x] 源不存在 → `404`,映射到 `skillRenameNotFound` 红字"原技能不存在"。
- [x] selectedPath 是被改名的 skill → 同步写 localStorage,跨 tab 刷新后选中态不丢。
