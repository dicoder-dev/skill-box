## 4. 问题与方案

### 4.1 拖拽后分组被折叠

**现象**:用户展开「分组 1」拖文件到「分组 2」→ 树刷新 → 全折叠。

**根因**:`store.load()` 末尾无条件 `if (!keyword.value) collapseAllGroups()`;`moveSkill/moveGroup/createGroup/deleteGroup` 等所有写操作后面都跟 `await load()`。

**方案**:折叠态不再无条件重置,改"内存 Set 为空才默认全折叠";已有内容时直接用持久化数据恢复。

### 4.2 simplify 复审抓到的 altitude 问题

**现象**:5 处 `saveCollapsedPaths()` 散点调用(`toggleCollapse` / `collapseAllGroups` / `rewriteGroupPathRefs` / `expandAncestorsOfPath` / load 末尾 prune 后)。

**方案**:抽一个 `watch(collapsedPaths, () => saveCollapsedPaths(), { deep: true })` 在 store 顶层接管所有落盘,删除 5 处手工调用。同时让 `saveCollapsedPaths` 顺手过滤 stale path(只写当前 tree 里还存在的 group),删除独立的 prune 函数。

### 4.3 hasInitializedCollapse flag 是治标

**现象**:派生属性"是否初始化过折叠态"被外挂成一个 `let` flag。

**方案**:用 `collapsedPaths.value.size === 0` 隐含表达 — 空 Set = 没初始化过(刚装或外部清掉 localStorage)。

### 4.4 collectGroupPaths 重复 3 次

**现象**:`collapseAllGroups` / `pruneStaleCollapsedPaths` / `autoExpandMatchedPaths` 三处都内嵌了一份递归 group path 收集。

**方案**:抽顶层 helper `collectGroupPathsInTree(predicate?)` 共享骨架,predicate 控制是否收集。
