## 4. 问题与方案

### 4.1 误解"目录树"为首页左侧 skill 树(关键教训)

**现象:** 第一轮把菜单改造全打到 `SkillsView.vue` 左侧树(`TreeNode.vue`),用户说"在那儿右键了没反应"。

**根因:** 用户原话"技能目录树"语义模糊,既可指首页左侧"skill 分组树"也可指详情区"skill 包内文件树"。我默认了前者,做了一整轮 + 推到 main,用户反馈后才意识到位置错了。

**教训:**
- 涉及"右键菜单 / UI 改造"时,**第一步必须确认作用域**:到底是哪个具体的树、面板、组件?不能靠"猜"。
- 第一轮 commit 之前应该用 AskUserQuestion 跟用户确认范围(虽然上一轮我确认了后端方案 + 弹窗形式,但**没确认"是哪个树"** — 这是遗漏)。
- 错位的 commit 通过 `git revert` 干净撤销,后端 RenameSkill 用单独 commit 保留(它是有价值的)。

### 4.2 后端无独立文件 CRUD 端点

**现象:** 需求是"重命名文件 / 删除文件 / 新建文件 / 新建目录",但后端 controller 目录里只有:
- `create_skill` / `update_skill` / `delete_skill` / `rename_group` / `rename_skill` / `move_*`
- **没有 `create_file` / `delete_file` / `rename_file` / `create_dir`**

**方案:** 复用现有 `updateSkill({...files})` 链路:
- `store.Save` 走覆盖式:先 `os.RemoveAll(dir)` 再 `os.Rename(tmp, dir)`(store.go 行 147-153)
- `files` 数组塞任意 path + content,后端遍历写到磁盘;**新 path 自动 mkdir -p 父目录**(store.go 行 138-144)
- "删除文件" = 从 files 数组里 filter 掉
- "重命名文件" = map 改 path
- "新建目录" = 塞一个 `<dir>/.gitkeep` 占位文件(避免空目录被 ListTree 过滤)
- 唯一不变量:SKILL.md 由后端按 manifest 重新生成,前端不能从 files 数组里删 SKILL.md(保护: validateFsName + submitDeleteFile 双重拦截)

**为什么这个方案更好:**
- 0 个新后端端点,0 个新 store 方法,0 个新 service 方法
- 复用现有 `updateSkill` 的所有逻辑(权限 / 校验 / 锁 / 写盘 / 通知)
- 前端只跟"files 数组"打交道,语义最自然

### 4.3 SKILL.md 不能直接 CRUD

**现象:** 用户右键"SKILL.md"时,弹出"重命名 / 删除",但 SKILL.md 是 skill 的元数据容器,后端按 manifest 重新生成,前端改它没意义(下次 save 又被覆盖)。

**方案:** 双层保护:
- `validateFsName()` 在新建弹窗拒绝 `SKILL.md` 作为文件名
- `submitDeleteFile()` 在删除弹窗拒绝 `target.path === 'SKILL.md'`,toast 提示"SKILL.md 由系统管理"

### 4.4 根区域 vs 文件/目录行的右键冲突

**现象:** 三个位置都要右键弹菜单,但只有"根区域"对应 `.file-tree-view` 容器,文件/目录行是容器内的子节点。

**方案:**
- FileTreeNode 在 @contextmenu 内 `e.stopPropagation()`,阻止冒泡到 .file-tree-view
- FileTreeView 在 .file-tree-view 容器 @contextmenu,只在子节点没拦截时触发 = 根区域
- 子节点拦截的 context-menu-file / context-menu-folder emit 由 FileTreeView 转发到 InlinePanel
- FileTreeView 自己的 context-menu-root 也 emit 到 InlinePanel

测试:用户点空白处 → 根菜单;点文件行 → 文件菜单;点目录行 → 目录菜单。三者互不干扰。

### 4.5 删除目录需要递归

**现象:** 详情区"目录"在 files[] 里没有独立表达,只是"path 前缀相同的一组文件"。

**方案:** `openDeleteFolderDialog` 收集 `dir.path + '/'` 前缀的所有文件路径,`submitDeleteFile` 用 `filter(f => f.path !== target.path && !f.path.startsWith(prefix))` 一次性删空。

### 4.6 目录创建走 .gitkeep 占位

**现象:** `store.Save` 不会显式创建空目录 — 它只写 files 里的 path。如果只 mkdir 父目录但不放任何文件,后端 save 后目录又被 `os.RemoveAll(dir)` 整目录重写时空目录丢失。

**方案:** 创建目录时塞一个 `path = "<dir>/.gitkeep"` 的空文件(内容 = `''`),store.Save 会自动 mkdir `<dir>` 并写入 .gitkeep,空目录得以保留。FileTreeView 的 buildTree 过滤掉以 `.` 开头的路径,所以 .gitkeep 不会显示在用户面前。
