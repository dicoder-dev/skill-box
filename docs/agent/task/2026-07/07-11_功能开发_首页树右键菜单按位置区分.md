# 首页技能树右键菜单按位置区分(文档重命名/删除, 分组新建文档, 根新建文件夹/文档)

**日期:** 2026-07-11
**状态:** 已完成

## 1. 需求

用户原话: 「现在请你优化一下首页技能的'技能目录树'区域,我需要支持扩展更多功能,特别是目录的管理。具体要求是:根据不同的位置,对应显示不同的右键菜单功能选项:

1. 右键点击文档时:
   (a) 支持重命名文档
   (b) 支持删除文档
2. 右键点击分组(文件夹)时:
   (a) 支持新增文档
3. 右键点击根目录时:
   (a) 支持新增文件夹
   (b) 支持新增文档」

需求拆解:
- 三种位置的菜单项需互不重叠(避免用户重复操作)
- "重命名文档" 是新增能力,后端此前没有 RenameSkill 接口
- "新增文档" 在分组内需要在指定 group_path 下创建,需复用现有 InlinePanel 的 openAsNew 入口
- "删除文档" 已有 deleteSkill + 现有 DeleteConfirm 弹窗,直接复用

## 4. 问题与方案

### 4.1 重命名文档后端方案

**现象:** 后端没有 RenameSkill API。Update 走 Save 覆盖,但代码注释 "强制以目录名为准,不允许通过 Update 改 name(rename 走 Delete + Create)"。

**方案对比(与用户确认过):**
| 方案 | 优 | 劣 | 选 |
|---|---|---|---|
| 新增 RenameSkill API | 一次原子 os.Rename,O(1) 无 IO,失败可回滚 | 改 3 个 Go 文件,需新测试 | ✅ |
| 前端 Delete+Create 模拟 | 后端 0 改动 | 中途失败留空档;version 变了丢 apply 关联 | ❌ |
| 扩展 UpdateSkill 支持 name | 一致性更好 | 改 Save 行为可能影响其他链路 | ❌ |

**最终落地:** 参照 RenameGroupDir 风格新增 RenameSkillInGroup(store) → RenameSkill(service) → rename_skill(controller)。底层用 `os.Rename(srcAbs, dstAbs)` 在同 group 内换名(同文件系统下原子),失败降级到 `copyDirRecursive + RemoveAll`。

### 4.2 store 层 safeRelPath 拒绝空串问题

**现象:** `safeRelPath("")` 直接 `errors.New("empty path")`,导致"根下 skill 重命名"场景(入参 srcGroupPath="")走到 error 分支,测试 fail。

**方案:** 在 store 层把空 srcGroupPath 视作合法(根),跳过 safeRelPath;只对非空值做路径校验。注释里说"groupPath 允许空(根),但含 .. / 绝对路径 / NUL 仍拒"。

### 4.3 三个右键菜单的拆分

**现象:** 改造前三个右键菜单都有"在文件夹打开 / 复制路径"等扩展项,改造后需要按位置重新设计。

**取舍:**
- 文档(skill 节点):只保留"重命名 + 删除"。原来"在文件夹打开 / 复制路径 / 打标签"在详情区顶栏(详情区可见的 skill 已经有完整工具栏),树右键冗余。
- 分组(group 节点):只暴露"新建文档"。用户明确要求,其他动作后续再做。
- 根区域:暴露"新建文件夹 + 新建文档"两条。两条无依赖,跟需求一致。

**关键决定:** 旧 `onSkillContextMenu` / `onGroupContextMenu` 里调的 `openSkillInFolder` / `openSkillTagDialog` / `openGroupInFolder` 等函数**没有删**,后续分组重命名/删除分组 等扩展需求回来时直接复用。

### 4.4 文档重命名后选中态处理

**现象:** 旧 path 选中的 skill 重命名后,selectedKey 还指旧 path,需要切到新 path。

**方案:** 重命名成功后 reload 列表 + 用 new_skill_path 反查新 row + selectItem。失败容忍(找不到 row 不报错,因为用户可能没选中)。

### 4.5 新建文档透传 group_path

**现象:** InlinePanel.openAsNew 接受 `initial.group_path` 字段(已在原代码 587 行使用),createSkill payload 也带 `group_path`(`{scope, project_id, name, version, source, group_path, manifest, files}`)。

**方案:** 直接复用现有通道,不需要动 InlinePanel 任何代码。
