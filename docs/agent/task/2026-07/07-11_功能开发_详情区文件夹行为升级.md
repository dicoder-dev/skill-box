## 4. 问题与方案

### 4.1 问题 1 + 2 的根因:写占位文件到磁盘

**之前设计**:前端新建文件夹时,在 files 数组里塞 `<dir>/.skillbox-placeholder` 占位条目,走 updateSkill → store.Save 真写到了磁盘。

**用户视角问题**:
- chip 显示 `(files || []).length` = 包含占位文件(2 个文件 + 1 个占位 = 3 个)
- 展开目录:buildTree 把占位文件过滤掉(白名单),用户**看不到任何文件**但 count 是 1
- **认知冲突**:视觉上"目录是空的",但 chip 提示"有 1 个"

**新设计**:
- 新建文件夹**不**写任何占位文件
- 走 `createGroup` 端点(`/api/skillbox/skills/group/create`),只创建物理目录
- files 数组不变,后端 `loadFromDir` 走 `listEmptyDirs` 在响应时**临时**补占位条目
- 前端 buildTree 走 BUSINESS_PLACEHOLDERS 白名单,占位条目**不进** users.files 数组

**结果**:
- chip 显示真实的 file 数量(不含占位)
- 展开空目录:用户看到的是"真的空"目录,count 0
- 刷新页面:`loadFromDir` 重新跑 listEmptyDirs 补占位,目录仍可见

### 4.2 问题 3 的根因:文件夹右键只支持新建

之前为简化只暴露"新建文件"一个项,用户需要更多操作。

**新菜单**:
1. **新建文件** (保留)
2. **--- 分隔符 ---**
3. **重命名文件夹** (新增) — 复用重命名文件弹窗,把所有 `<oldDir>/` 前缀的 path 替换成 `<newDir>/`,走 updateSkill
4. **在文件浏览器中打开** (新增) — `platform.fs.reveal(物理目录绝对路径)`,绝对路径 = `skill.canonical.source_dir` + `dirPath`

### 4.3 重命名文件夹的实现细节

**校验**:
- 文件名规则(`validateFsName(name, 'dir')`):不允许 `/` / `\` / `.` / `..`,不为空
- 新名 ≠ 旧名(否则按钮 disabled)

**文件路径变换**:
```
旧结构:
  files = [
    { path: 'oldDir/file1.md' },
    { path: 'oldDir/subdir/.skillbox-placeholder' },
  ]
重命名为 'newDir':
  files = [
    { path: 'newDir/file1.md' },
    { path: 'newDir/subdir/.skillbox-placeholder' },
  ]
```

**对虚拟 .skillbox-placeholder 占位条目**的特殊处理:
- 它的 path 形如 `<dir>/.skillbox-placeholder`
- 旧 prefix 是 `oldDir/`,替换成 `newDir/`
- 这种条目在 loadFromDir 时会被 listEmptyDirs 补,**重命名后 listEmptyDirs 重新跑**会重新补新的 placeholder 路径

### 4.4 在文件浏览器中打开

**绝对路径构造**:
```js
const srcDir = skill.canonical?.source_dir || skill.canonical?.source_path || ''
const abs = dirPath ? `${srcDir}/${dirPath}` : srcDir
```

`source_dir` 是后端在 `loadFromDir` 里 `filepath.EvalSymlinks(dir)` 写入的(`store.go` 行 240+),保证 symlink 链上 path 不漂移。

**调 platform.fs.reveal** —— 复用 SkillsView 已有的 in-folder 打开逻辑(同 platform.fs.reveal + 兜底 openExternal)。
