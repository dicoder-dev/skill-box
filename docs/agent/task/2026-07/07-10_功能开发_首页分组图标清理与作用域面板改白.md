## 4. 问题与方案

### 4.1 caret 删除后树对齐问题

**现象:** TreeNode 模板(行 200)用 `paddingLeft: ${depth * 14 + 4}px` 做缩进,group 行内 folder 图标原来在 caret 右侧。删 caret 后 group 行内 folder 图标左移 16px,与展开后的子节点(folder/技能)水平不对齐。

**方案:** 在原 caret 位置插一个 16px 宽的 `span.tree-caret-spacer`(`display: inline-block; width: 16px; flex-shrink: 0`),视觉不可见但占住宽度,树对齐保留。`.tree-caret-spacer` 样式原本就存在(行 344-348)但只在 CSS 里定义、模板里没用 — 正好复用,顺手把宽度从 14px 改成 16px 与原 IconPark 16x16 等宽。

**教训:** 写 CSS 占位 class 是个好习惯 — 即使模板里没用到,后续视觉调整可以零成本复用。

### 4.2 "作用于区域"面板用户之前 v6 改成灰底,现在又要改回白底

**现象:** SkillScopePanel 行 475-477 注释明确写过 v6 改回 var(--bg-subtle) 灰底是因为"用户反馈『面板是白底』『标题不灰』"。今天用户又要"由灰色改成空白色",看似反转。

**判断:** 这是用户主动的产品决策改变(可能与其它 UI 改造配套),不是 bug。严格按用户原话执行 —— `.ssp-scope` 整体改 `var(--bg-card)`,header(`.ssp-scope-header-toggle`)仍 `var(--bg-subtle)`,靠 header 自带的 `border-bottom: 1px solid var(--border)` 自然分隔 header 和 body。

**教训:** "用户之前要 X,现在又要 not-X"不一定是矛盾 — 可能是阶段性设计调整。注释里 v6 留下的"反馈记录"也要在 commit 信息里说明,便于后续回看。
