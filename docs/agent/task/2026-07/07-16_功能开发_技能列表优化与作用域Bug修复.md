## 4. 问题与方案

### 4.1 作用域点击关闭左侧目录(Bug 根因)

**现象:** 右侧 SkillScopePanel 点击"全局 Agent Skill"开关后,左侧 TreeNode 当前选中的 skill 卡片被收起。

**根因链路:**
1. `SkillScopePanel.vue:321` 在 toggle 完成后 `window.dispatchEvent(new CustomEvent('skillbox:scope-refresh'))`
2. `SkillsView.vue:1693` `addEventListener('skillbox:scope-refresh', onScopeChange)`
3. `onScopeChange()` → `skillTree.load({ keyword: ... })`
4. `skill-tree.js:230-232` 非搜索态下 `collapseAllGroups()` 整体替换 `collapsedPaths.value`
5. 当前选中 skill 的祖先 group 被折叠 → 左侧看不到当前选中行(用户感受:被关闭)

**对比:** `reload()` 路径(初始化 / 显式刷新)在 load 后会调 `expandAncestorsOfPath()`,但 `onScopeChange()` 走的是裸 `load()`,没有这一步,这是漏掉的"恢复选中可见性"。

**方案选型:**
- 方案 A:在 SkillsView.onScopeChange 里 load 后再调 expandAncestorsOfPath(局部修补)
- 方案 B:在 store.load 内部加 `if (selectedPath.value) expandAncestorsOfPath(selectedPath.value)`(对所有走 load 的路径生效,更通用)

**采用方案 B**。理由:store.load 是所有 reload/refresh 的统一入口,把"load 后保留选中可见性"下沉到 store,自动覆盖:
- SkillsView.onScopeChange(scope-refresh)
- SkillsView.onSkillsRefresh(skills:refresh)
- 未来的 MarketView 跳 tab / 设置变更触发 load 等所有路径

**风险评估:**
- 用户主动 reload(显式点刷新按钮)→ load → collapseAll → 展开选中祖先 → 行为与之前一致(因为 reload 之前就有 expandAncestorsOfPath 在外部调,只是现在下沉到 store 内)
- 用户主动全折叠(假如未来加全折叠按钮)→ 那时需要先 clearSelected 再 load,但当前没有这个按钮,无回归风险
- selectedPath 在新 tree 里找不到(被删除/移走)→ expandAncestorsOfPath 内部 `existsInTree` 校验,静默返回,不乱展开

**教训:** "selectedPath 持久化 + collapseAllGroups 默认折叠"两个特性叠加时,必须在 load 末尾加"恢复选中可见性"一步,否则选中态在视觉上消失但 state 还在,用户感知为"被关闭"。以后任何 store.load 的修改都要同步检查这一对不变量。
