## 4. 问题与方案

### 问题 1:Edit 多次替换导致 SFC 块重复

> 现象:第一次 `npm run build` 报 "Invalid end tag",定位发现 164 行出现了一个孤悬 `</script>`,后面跟着旧的 navItems computed。
> 定位:第一次替换 script 段时 old_string 在原文件中间的某个位置截断,只换掉了前 3/4,留下尾巴。
> 方案:用 `grep -n "^<script\|^</script..."` 列出所有 SFC 边界,确认只剩一个 `<script>` / `</script>` / `<template>` / `<style>` 即可。
> 教训:**重写 SFC 大段时,优先 Read 完整文件 + 一次性 Write 替换整个文件**,不要分段 Edit 拼凑。

### 问题 2:旧函数重复声明(navItems / switchTab / onBusEvent / onWindowEvent)

> 现象:第二次 / 第三次 build 报 "Identifier 'X' has already been declared"。
> 定位:164 行的旧 script 块尾巴里保留了 navItems computed + switchTab + onBusEvent + onWindowEvent 四份定义。
> 方案:同样靠 grep 列出每个标识符的所有出现位置,把重复段落整段 Edit 删掉。
> 教训:同问题 1,需要先 `grep -c` 自查重复再 build。

### 问题 3:chrome-devtools MCP 不可用

> 现象:`mcp__chrome-devtools__new_page` / `list_pages` 全部返回 "browser already running",无法做视觉自测截图。
> 定位:MCP 实例冲突,要求 isolated context 才能开新 session,本环境启动参数受限。
> 方案:跳过视觉截图,通过以下三项保证质量:① vite build 通过(无模板编译错误);② go build 通过(embed 链路通);③ 静态 grep 校验新类名 / 新结构 / i18n key 全部就位;④ 完整读 App.vue 新版 template/style 段人工审一遍。
> 教训:视觉自测 MCP 不可用时,要明确说明改用静态校验 + Go 编译验证,把"无法在浏览器截图"写进测试报告的"未做"项。
