# 首页分组仅支持单级,移除右键新建子分组

**日期:** 2026-07-03
**状态:** 已完成

## 1. 需求

> 首页分组中 请你修改:目前先仅支持单击分组不支持多级分组;不应该后端 前端界面修改即可 右键分组不支持新建子分组

解读:
- 首页左侧 skill 分组树,目前支持多级嵌套(树形递归渲染)。
- 改:仅支持单击分组展开/折叠(语义不变),**不再展示多级嵌套**(后端不动,前端改 UI)。
- 改:右键分组的菜单里,移除"新建子分组"项。

后端不动,纯前端。

## 3. 执行进度

- 找到 `frontend/src/components/TreeNode.vue`(递归子节点 `<TreeNode v-if="node.is_group && ..."/>`)和 `frontend/src/views/SkillsView.vue` 的 `onGroupContextMenu`(`new-sub` 项,i18n key 是 `ctxNewSubgroup`)。
- 决定:既然后端不动,前端用 `flattenSingleLevel` 函数把后端可能仍返回的嵌套 children **拍平到当前 group 的一层**(深层 group 节点丢弃,只保留其叶子 skill),这样老数据也不影响。
- 同时**直接删掉**模板里的递归 `<TreeNode>` 节点,起到"硬保险"作用 — 即便 props.nodes 直接传嵌套结构,这里也不会再展开。
- SkillsView `onGroupContextMenu` 去掉 `new-sub` 菜单项,i18n key `ctxNewSubgroup` 保留(留作历史,无引用)。
- i18n `groupNamePrompt` / `groupNamePromptSub` 改为"只支持单级,不能含 /"(和首页行为对齐,避免用户继续按 / 创建)。

## 4. 问题与方案

- **问题 1:** 改 TreeNode 时第一次 Edit 把 `displayNodes` 错插到 `const props = defineProps(` 之后,导致 props 的多行参数被切散。
  - 方案:用第二个 Edit 把 `displayNodes` 重新挪到 `defineProps` 之后(在 `defineOptions` 之前),整理干净。提交前再 Read 一次确认结构正确。
- **问题 2:** 后端仍在返回嵌套 tree(后端没动),如果只删递归模板不拍平,叶子会全丢。
  - 方案:加 `flattenSingleLevel` 函数,把每个 group 节点下的"任意深度的叶子 skill"收集到该 group 的单层 children 里,深层 group 节点本身丢弃。后端怎么返回都不会影响前端 UI 效果。
