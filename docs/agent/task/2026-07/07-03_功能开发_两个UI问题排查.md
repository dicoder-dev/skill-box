## 4. 问题与方案

### 4.1 删除/更换自定义图标按钮点击没反应

**现象:** 用户在编辑工具弹窗里点"上传自定义"按钮,文件选择对话框没弹出。

**根因:**
1. `<input ref="iconFileInput" type="file" class="hidden-input">` 的 CSS 是 `display: none`。
2. 点击"上传自定义"按钮 → `pickIconFile()` → `iconFileInput.value.click()`。
3. **浏览器对 `display:none` 的 input 调用 `.click()` 不弹文件选择对话框** — 因为该元素不在渲染树里,浏览器认为不可交互。

**方案:** 改用更稳的 `<label for="...">` 模式:
- 把 "上传自定义" 按钮从 `<button @click="pickIconFile">` 改成 `<label for="tool-icon-input">`,浏览器原生支持"点 label 触发对应 input 的文件选择"。
- 同时给 hidden input 加 CSS `position:absolute; width:0; height:0; opacity:0; left:-9999px`(0 大小 + 屏幕外),即使被 `.click()` 也能弹文件框。
- 删掉 `iconFileInput` ref 和 `pickIconFile` 函数(由 label-input 关联替代),减少 Vue ref 跨 Teleport 的不确定性。
- onIconFileChosen 里直接用 `e.target` 重置 input.value,不用通过 ref。

**为什么这样更稳:**
- `<label for>` 是 HTML 规范保证的"点 label 等价于点 input"行为,不受任何 CSS 样式影响。
- 不依赖 JS 调用 `input.click()`,即使 input 完全 display:none 也能触发文件框。
- 减少 Vue ref 使用,跨 Teleport/Modal 也不会出问题。

### 4.2 系统工具图标没替换

**现象:** 联网搜集了新 logo 并放到 builtin-icons/ 里,但 UI 上系统工具的图标还是老的占位图(可能就是"原始的"无品牌图标)。

**根因:**
1. `EnsureSeeded` 的判定逻辑是"e_tool 表 Count() > 0 就跳过 seed"。
2. 用户之前已经跑过 seed(我之前手动启动 + 桌面端启动都跑过),所以 DB 里有 9 行工具记录,后续启动全部走 skip 分支。
3. DB 里 `icon_file` 字段存的是老文件名(`cursor.png` / `trae.png` 等),即便 `writeBuiltinIcons()` 把新文件 `cursor.ico` / `trae.ico` 写到了磁盘,前端 `iconSrc` 还是会去请求老文件名 → 404。
4. **用户不需要"删掉工具"重建** — 那会丢失自定义 enabled / paths 配置,且更暴力。

**方案:** 在 `EnsureSeeded` 的 skip 分支里加一个轻量迁移函数 `refreshSystemIconFiles`:
- 遍历 9 个内置工具,对比 `cur.IconFile` 与 `bt.IconFile` (builtins 里最新值)。
- 不一致时 `db.Model(cur).Update(mtool.FieldIconFile, bt.IconFile)` 单字段更新。
- 一致时跳过(避免无谓 update,日志也不刷)。
- **只动 is_system=true 的系统工具的 icon_file 字段,不动 display_name / mdi_icon / paths / enabled 等用户可能已自定义的字段**。

**为什么不直接抹平全表重建:**
- 用户可能改过 enabled=false 或排过 path 顺序,删行重建会丢。
- 单字段 update 是 idempotent — 字段值已对就跳过,可以放心每次启动都跑。
