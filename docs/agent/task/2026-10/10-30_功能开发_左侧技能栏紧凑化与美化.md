## 4. 问题与方案

### 4.1 调研结论(顶级设计范式)
来源:marioaguzman Sidebar Guidelines(macOS source list 官方风格指南)、
uxpatterns.dev Sidebar Pattern、Linear / VS Code / Arc 通用范式。

要点:
- **侧栏宽度**:225-275pt 合理区间(本项目 260px 已在区间内,不动)
- **分组靠留白,靠横线切割是反模式**:密集侧栏用间距 / 背景色块分层
- **选中态三选一**:背景色 / 文字色 / 左侧色条 —— 不用光晕阴影
- **hover**:中性灰底(gray.200 底 + gray.900 字)
- **item 内边距**:0.5rem 纵向 / 1rem 横向,0.875rem 字号
- **分组标题**:可省略;需要时用更小字号 + semibold + 字距
- **搜索框**:条目多时应在顶部
- **动作分层**:工具栏不堆控件,重要操作可放上下文菜单

### 4.2 CSS 优先级坑(本次真实踩到)
第一次加完"淡底 + 左色条"选中态,截图发现色条没出现、边框仍是蓝边。
定位:`.tree-node-selected > .tree-row` 这条通用规则(2 个 class = 特异度 0,2,0)
与 `.tree-node-selected > .tree-row-skill` 同特异度,但写在后面 → 覆盖了后者,
把底色刷回 `--bg-card`、边框刷回 `--accent-blue`。
方案:通用规则加 `:not(.tree-row-skill)` 排除 skill 行,让 skill 行走专属样式。

### 4.3 暗色模式对比度
主按钮用 `background: var(--accent-blue)` + `color: #fff`。
暗色模式下 `--accent-blue` 是亮蓝 `#60a5fa`,白字对比度仅约 2.3:1,远低于 WCAG AA 的 4.5:1。
方案:新增语义 token `--accent-blue-fg`(浅色 `#ffffff` / 暗色 `#0a0a0a`),
不各处硬编码 `#fff`。

### 4.4 截图误判
中途截图看到暗色模式文字发暗,一度以为样式有问题。
实际是 CSS `transition` 中途的帧(读 `getComputedStyle` 拿到 rgb(115,115,115) 这种
中间值)。等 transition 结束(0.15s)后重读为 rgb(10,10,10),正常。
教训:带 transition 的样式截图/取值要等动画结束再判断。
