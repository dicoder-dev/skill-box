## 4. 问题与方案

### 4.1 调研结论(顶级设计范式)
来源:marioaguzman Sidebar Guidelines(macOS source list 官方风格指南)、
uxpatterns.dev Sidebar Pattern、Linear / VS Code / Arc 通用范式。

要点:
- **侧栏宽度**:225-275pt 合理区间(本项目 260px 已在区间内,不动)
- **分组靠留白,靠横线切割是反模式**:密集侧栏用间距 / 背景色块分层
- **选中态三选一**:背景色 / 文字色 / 左侧色条 —— 不用光晕阴影
- **hover**:中性灰底(gray.200 底 + gray.900 字)
- **item 内边距**:0.5rem 纵向 / 1rem 横向,0.875rem 字号
- **分组标题**:可省略;需要时用更小字号 + semibold + 字距
- **搜索框**:条目多时应在顶部
- **动作分层**:工具栏不堆控件,重要操作可放上下文菜单

### 4.2 CSS 优先级坑(本次真实踩到)
第一次加完"淡底 + 左色条"选中态,截图发现色条没出现、边框仍是蓝边。
定位:`.tree-node-selected > .tree-row` 这条通用规则(2 个 class = 特异度 0,2,0)
与 `.tree-node-selected > .tree-row-skill` 同特异度,但写在后面 → 覆盖了后者,
把底色刷回 `--bg-card`、边框刷回 `--accent-blue`。
方案:通用规则加 `:not(.tree-row-skill)` 排除 skill 行,让 skill 行走专属样式。

### 4.3 暗色模式对比度
主按钮用 `background: var(--accent-blue)` + `color: #fff`。
暗色模式下 `--accent-blue` 是亮蓝 `#60a5fa`,白字对比度仅约 2.3:1,远低于 WCAG AA 的 4.5:1。
方案:新增语义 token `--accent-blue-fg`(浅色 `#ffffff` / 暗色 `#0a0a0a`),
不各处硬编码 `#fff`。

### 4.4 截图误判
中途截图看到暗色模式文字发暗,一度以为样式有问题。
实际是 CSS `transition` 中途的帧(读 `getComputedStyle` 拿到 rgb(115,115,115) 这种
中间值)。等 transition 结束(0.15s)后重读为 rgb(10,10,10),正常。
教训:带 transition 的样式截图/取值要等动画结束再判断。

### 4.5 「两侧空白太多」的定位与解法(第二轮)
用户第二轮反馈「两侧的空白区域太多了」。我先做了客观扫描
(逐列 `elementFromPoint` 采样 + 各容器 boundingRect),发现页面有 4 处
可能的空白来源,于是用 AskUserQuestion 让用户确认,结果是
**最左侧技能列表行内**。

三个叠加原因:
1. **栏宽 260px 对短名字太宽** —— skill 名普遍 8-12 字符
   (code-review / commit-msg),名字右侧能空出 100px+。
2. **行内元素本身松** —— 图标槽 16px + gap 6px + padding 10px 一套下来,
   视觉重心偏左,空白感被放大。
3. **`.tree-name` 是 `flex: 1`** —— 名字撑满整行,右侧那段空白
   虽然"没人占",但视觉上就是一块死白。

解法(缺一不可):
- 栏宽 260 → **224px**(macOS Sidebar Guidelines 推荐 225-275 区间),
  详情区正文因此变宽 36px,一举两得。
- 行内收紧:padding 5/10→4/8、margin 3/4→2/2、图标槽 16→14px、
  skill 名 13→12.5px。
- **版本号回填右端** —— 只收窄 + 收紧的话,`.tree-name` 仍 flex:1,
  右侧空白依然在。补上版本号贴右(margin-left:auto + 极淡色)后,
  空白带被真实信息填满,不再是死白。
  这是顶级 source list 惯例(VS Code 资源管理器在文件右侧显示
  大小 / git 状态),既消除空白又提供信息。

### 4.6 版本号"复活"的历史包袱
`git log -S tree-version` 查到 2026-07-16 的 commit 911b8f1
「缩小左侧技能列表宽度并隐藏列表版本号」—— 当时移除的原因是
栏宽 320→260 太挤,名字+版本号挤一行。
现在栏更窄(224)、行更扁(单行无副标题),完全放得下,
所以恢复它是合理的,不是推翻旧决策。

### 4.7 localStorage 宽度迁移(老用户看不到效果)
`useResizablePanel` 把宽度持久化到 `localStorage`
(key = `skillbox:panel:skills-list-w`)。只改 `defaultWidth` 对
**已经用过的老用户无效** —— 他们本地存着 260,照样渲染 260。
方案:在调用 composable 前做一次迁移,只在存的宽度**恰好等于旧默认 260**
时删掉存储;用户手动拖过的自定义值(如 320)说明是明确选择,原样保留。
回归验证:存 260 → 生效 224;存 320 → 保持 320。

### 4.8 搜索功能不生效 = 既有问题,非本次引入
自测时发现搜索框输入 "debug" 不过滤列表。用 `git stash` 切到基线版本
复测,**基线同样不过滤**,确认与本次改动无关。
根因(未修,属另一个问题):`filteredItems` computed 基于旧的 `items`
列表做过滤,但渲染早已改用 `skillTree.tree`,过滤链没接上。
