## 4. 问题与方案

### 4.1 现有实现是"多源 failover",不是"按语言选源"

**现象**:现有代码 `DefaultManifestURLs` 返回固定顺序的 url 数组,谁先谁后由配置决定。
**定位**:schema 本来就是 `urls[]` 数组 + 按顺序降级,天然兼容"按语言排序"。
**方案**:不推翻架构,把"固定顺序"改成"按 locale 排序",另一源保留为兜底。

### 4.2 后端拿不到用户语言

**现象**:`RequestUpdateCheck` 原本是空 struct。
**方案**:前端 query 传 `lang`(zh-CN / en-US),后端 `ShouldBindQuery` 绑定。
**不用** Accept-Language —— 桌面端 webview 那条链路不受控。

### 4.3 选源只做一半(manifest 换了站、安装包没换)

**现象**:如果 manifest 是从 Gitee 拉的,但里面 `assets[].urls` 仍指向 GitHub,等于没分源。
**方案**:两站各托管一份 manifest 指针文件(`manifest.github.json` / `manifest.gitee.json`),
除 `urls` 指向各自站点外内容一致。选哪份 manifest,安装包就从同一个站下。
兜底换源时安装包地址自动跟着换(因为 urls 本来就是该站自己的)。

### 4.4 manifest 缓存串源

**现象**:原缓存键只有 `channel`。切语言后拿到的是上一个源的 manifest(内容不同)。
**方案**:缓存键 = channel + 源 url 列表的 fnv 哈希。

### 4.5 release.sh 的两个历史 bug

- `assets[].urls` 写死 `[]` → 下载必失败("asset has no urls");
- `arch` 写死 `"amd64"` → macOS universal 包在 arm64 机器上匹配不到 asset。

**方案**:脚本按实际产物生成;macOS universal 包同时登记 arm64 / amd64 两条 entry 指向同一 zip。

### 4.6 Gitee 附件 100MB 上限

**现象**:`bin/Skill-Box` 85MB,Windows 安装包更大,Gitee 附件上限 100MB。
**方案**(用户选定):macOS `.app`、Windows `.exe` 统一压 zip;仍超限的 asset 只进 GitHub,
Gitee 那份 manifest 直接不放它。

### 4.7 Gitee 分支名 / raw 地址

**现象**:Gitee 新建仓库默认分支可能是 `master`,raw 地址分支名写错直接 404。
**方案**:`GITEE_BRANCH` 可配(默认 main);文档里写明必须与仓库实际分支一致。

### 4.8 跑后端会写回仓库里的 configs.yaml

**现象**:`go run ./cmd/web` 会把配置默认值写回 `api-server/configs.yaml`(多出 `llm_enabled` / `template` 两行)。
**方案**:测试用 `CONFIG=/tmp/.../configs.yaml` 指向临时文件;发现污染后 `git checkout --` 还原。

### 4.9 选源逻辑放哪(跨模块)

**现象**:桌面端模块 `skill-box` 与后端模块 `ginp-api` 都要用选源逻辑,Go 的 internal 规则禁止跨模块 import internal 包。
**方案**:新包放 `api-server/pkg/updatersrc`(pkg 不受 internal 限制)。
